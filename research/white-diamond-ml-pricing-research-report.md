## Executive summary

**The problem:** StarGem wholesale lab-grown diamond prices are not generated by one smooth function of carat and grade. The same nominal spec (shape, color, clarity, carat band) often contains **multiple price modes** (old rate card vs current list, commodity vs premium cut, specialty faceting vs standard). Any model must either **interpolate** the sheet accurately or **extrapolate** to unseen specs with defensible gem-market structure — usually not both in a single unconstrained estimator.

**What ships today (white):** **S26** — champion **policy** blending StarGem **lookup reconstruction**, monotone-capped **S22/S23** trees, and (in the app) live **comps**. Row-holdout MAPE ~**5.4%**; best MdAPE on dense cells (~**1.9%**). It is **piecewise constant in carat** (bucket steps) — correct for audit, not the long-term continuous pricing law.

**Production decision (2026-06-01):** **Keep S26** for displayed prices. Do **not** ship S28, S29, S30, or S31 as the production point estimate yet. See [`production-white-ml-model-decision.md`](production-white-ml-model-decision.md).

**What we built since the S28 v0.2 prototype:**

| Model | Role | Row holdout MAPE | Verdict |
|-------|------|------------------:|---------|
| **S28 v0.4** | Monotone parametric surface (re-fit) | **10.6%** | Structural law fixed; still ~5pp behind S26 on dense cells |
| **S29** | S28 + EB cell offsets + cut-tier + monotone residual | 8.2% in-cell (Python); **17.8%** cold cells (= S28) | Research scaffold; **1/4** release rules; Node surface ≠ S28 until re-export |
| **S30** | Per-spec bounded smooth median curves | **4.5%** fair train-only; **3.9%** shipped (optimistic) | Best accuracy where curves exist (~97% rows); no cross-grade transfer |
| **S31** | S28 + support-shrunk monotone anchor grid | **8.5%** | −2.1pp vs S28 on rows; **does not beat S28 on held-out cells** (9.9% vs 9.6%) |

**S28 v0.4** fixed the dangerous v0.2 bug (`colorRank_size` / `clarityRank_size` made $/ct fall with carat for common grades). Full-grid monotonicity: **0/56** carat inversions; live Node matches Python artifact. It remains the best **single** monotone surface for sparse extrapolation ([`model-selection-monotone-gradient-findings.md`](model-selection-monotone-gradient-findings.md)).

**Recommended near-term architecture** (research + charts, not production swap):

```text
User query

  → else S30 fair curve (if spec group has train-only curve)
  → else S31 guarded anchor / S28 surface (extrapolation floor)
  → R0 reconcileWholesale + conformal band (app)
```

**Colored gems:** Separate family — **S27 / Color S22** champion; do not route white S28/S29 into fancy-color stones.

## 1. Problem statement

### 1.1 What we need the system to do

| Task | User question | Success looks like |
|------|----------------|-------------------|
| **Interpolation** | “What does StarGem charge for this exact bucket today?” | Within a few % of the competitive list / lookup cell |
| **Extrapolation** | “What should a 7.77ct ROUND E VS1 cost if we have few 7.77ct rows?” | Monotone, plausible $/ct; no clarity/color inversions; tail scarcity not collapsed to commodity |
| **Explanation** | “Why is this number different from comps / ML?” | Source blend, support tier, out-of-range flags |
| **Trust** | “Is better clarity cheaper?” | Never on ladders or constrained surfaces |

### 1.2 Core tension

```text
Low MAPE on the historical sheet  ⟺  memorize buckets, eras, and bimodal tails
Safe extrapolation             ⟺  smooth law + constraints + fewer degrees of freedom
```

One unconstrained model optimizing only MAPE will:

- fit **premium and commodity** rows in the same cell;
- **step** at internal `carat_bucket` boundaries;
- **invert** clarity or color in sparse tree leaves (documented for S22);
- **collapse** large-carat tails (S25 negative global carat β).

The codebase **split roles**: S26 for dense policy, S28+ for structural surface, S30 for chart-faithful smooth medians. **Neither alone is the end state**; the tiered stack in the executive summary is the current best synthesis.

### 1.3 Why charts look “not log-shaped” and “not smooth”

Observed causes (not plotting bugs):

1. **Scatter:** Raw `starsgem-index` mixes rate-card eras (~2× spread for “same” spec). Clean training removes unexplained **high clusters** but still leaves many rows per cell.
2. **Lookup / S26:** Price is constant inside `carat_bucket`, then jumps at bucket boundaries — **not** because the market jumps there alone.
3. **S28 v0.2 (retired):** Global ridge surface under-leveled commodity cells; grade×size penalties inverted carat $/ct for E/VS1 — **fixed in v0.4**.
4. **S30:** Matches rolling medians on dense specs; clamps outside observed carat range (safe, not scarcity-extrapolating).
5. **Lab-grown commodity segment:** **$/ct** is often **higher at 1ct than 3ct** on the sheet (listing economics), so the cloud slopes down in $/ct even when **total price** rises with carat.

### 2.2 How the clean dataset is built

**Input:** `starsgem-index.json` (IGI-enriched; ~22,541 white rows).

**Style buckets** (examples — do not merge distinct IGI styles):

```text
ROUND_STANDARD, PEAR_STANDARD, PEAR_MODIFIED, PEAR_ICE_FLOWER,
OVAL_STANDARD, OVAL_MODIFIED, RADIANT_MODIFIED, HEART_STANDARD, …
```

**Cluster key (style-aware):**

```text
round(carat, 2) + shape_style + color + clarity
```

**Rules:**

1. Sort by $/ct within each group.
2. If largest consecutive jump ≥ **30%** and both sides are meaningful clusters (low ≥ 2, high ≥ 2, low count ≥ high count) → **quarantine high cluster** as `H_high_price_cluster`.
3. Else if lone point ≥ **40%** above group median → `F_extreme_outlier`.
4. Else → **`A_standard_recent`** (training).

**Intent:** Keep the **competitive / base** price surface; drop unexplained high tails (stale rate cards, unlabeled premiums). **Not** “lowest price only,” but “lower explained cluster when bimodal.”

See also: [`master-dataset-removal-audit.md`](master-dataset-removal-audit.md), [`same-spec-price-spread-examples.md`](same-spec-price-spread-examples.md).

**Builder:** `python3 research/scripts/dataset-split-outliers.py` → `npm run research:build-master-dataset`

### 2.3 What we are trying to get close to (target estimand)

ML is not trained to predict “any price StarGem ever listed.” The cleaned dataset defines a deliberate **target**:

| Layer | Definition | Use |
|-------|------------|-----|
| **Raw index** | All priced IGI-enriched rows in `starsgem-index.json` | Diagnostics, gray dots on charts, comp index |
| **Clean training (`A_standard_recent`)** | Rows that pass style-aware cluster rules | **Canonical ML target** |
| **Competitive list / lookup cell** | Median (or reconstructed rate) in `carat_bucket × shape × color × clarity [× cut]` on **current-window** stock | What **S26** chases (~5% MAPE row holdout) |
| **Continuous wholesale law** | Monotone $/ct in carat + grades, magic weights only, valid on **empty** cells | What **S28+** encodes; level calibrated via anchors (S31/S29) |
| **User-facing hero (R0)** | Reconciled wholesale from comps + ML + baseline rules | App headline; ML is one input ([`r0-decision-log.md`](r0-decision-log.md)) |

**In plain language, we want models to get close to:**

1. **“What does this supplier charge *right now* for stones like this?”**  
   → **Lookup + S26** on dense SKUs (e.g. 3ct ROUND E VS1 ≈ **$109/ct** commodity median).

2. **“What is a defensible wholesale $/ct for a spec we rarely stock?”**  
   → **S28 v0.4** (monotone law) or tiered fallback; not bucket stairs alone.

3. **“Never show impossible gem logic.”**  
   → Hard constraints on S28/S31 grids; display ladders may use **PAV** on tree policies.

**What we explicitly do *not* treat as ground truth:**

- Old rate-card rows left in the raw index.
- Unexplained **high-price clusters** quarantined as `H_high_price_cluster`.
- Premium ID/EX tails in the same cell as commodity CVD when the cluster rule keeps the **lower** mode.
- Alibaba comp medians as the ML label.

**Noise floor:** Segment A median absolute deviation from per-group median ~**2.77%** MAPE-equivalent (~3% global floor without label changes).


### 2.5 Row schema

Each object in `dataset-clean-training.json` is one priced stone. Key fields: `rowNo`, `carat`, `upc`/`price`, `shape`, `shape_style`, `color`, `clarity`, `typeName` (CVD/HPHT), IGI dimensions, `segment` = `A_standard_recent`.

**Important:** Training is on **physical style** (`shape_style`), not supplier shape label alone.

### 2.6–2.8 Data limits and pathology

“Cleaned” ≠ one price per spec — commodity and premium can coexist in one cluster.

| Can learn | Cannot reliably learn |
|-----------|----------------------|
| Dense 1–3ct round commodity | 4ct+ specialty with few rows per style |
| Shape/style modifiers with support | One global surface without cell anchor |
| Large stones where style bucket has rows | Exact 30ct IF premium if cell empty |

**Pathology still present:** temporal rate-card mixing; commodity vs premium in one bucket; specialty cuts at 2–6× standard; occasional data errors ($19/ct at 5ct+).

## 3. Model iteration history — what we have tried

Chronological summary. Earlier generations: `research/scripts/starsgem-mrpe-v2.py` (S7–S18); production iterated S19–S31.

### 3.1 Approach families

| Family | Idea | Strength | Failure mode |
|--------|------|----------|--------------|
| **Pure trees** (S7, S18, S20, S22) | ExtraTrees + lookup anchor | Low MAPE in dense cells | Clarity inversions; OOD flat/wrong |
| **Lookup residual** (S19–S20) | Predict `log(actual/lookup)` | Fixes “relearn the sheet” | Bucket-anchored |
| **Monotone boosting** (S21, S23) | LightGBM + monotone constraints | Grade ladders safe | Worse MAPE than S20 alone |
| **Champion policy** (S26) | Blend lookup + ML + comps | Best **interpolation** | Piecewise in carat |
| **Parametric** (S25, S28) | log($/ct) surface | Always prices; extrapolation | S25 broken tail; S28 level error until anchors |
| **Hybrid offset** (S29, S31) | Surface + shrunk anchors/residual | Level correction | S29 sparse explosions; S31 cold-cell transfer weak |
| **Median curves** (S30) | Smooth spec medians, bounded | Chart-faithful; best fair MAPE | No empty-cell transfer; ~3% missing curves |
| **Post-process PAV** (S22 display) | Isotonic on ladder | Display guarantee | Worsens point MAPE |

### 3.3 S28 v0.4 re-fit (2026-06-01)

**Artifact:** `s28-monotone-parametric-v0.4-grade-premium-no-vintage`  
**Docs:** [`s28-underpricing-diagnostic.md`](s28-underpricing-diagnostic.md), [`s28-monotone-parametric-trend-surface.md`](s28-monotone-parametric-trend-surface.md)

**What broke in v0.2:** `colorRank_size` and `clarityRank_size` (coefficients ≤ 0) penalized worse grades more as carat grew, overwhelming scarcity premium. Gates sampled only **ROUND D IF** (ranks zero) → bug shipped undetected. Live diagnostic: **−26.8%** bias, **97.9%** underpriced, **55/56** grid carat inversions.

**v0.4 fixes:**

```text
colorPremium   = (maxColorRank   - colorRank)   * log1p(carat),  coeff >= 0
clarityPremium = (maxClarityRank - clarityRank) * log1p(carat),  coeff >= 0
+ full ROUND {D..K} × {IF..SI2} carat ladder gate (0/56 inversions)
+ vintage disabled for live/Python parity
+ JS magic-weight labels aligned with Python (1_0ct, 2_0ct, …)
```

**Current metrics (row holdout, n = 4,415):**

| Metric | S28 v0.4 | S26 |
|--------|----------|-----|
| MAPE | 10.62% | **5.37%** |
| MdAPE | 8.20% | **1.94%** |
| Bias | +0.89% | −1.08% |
| Full-grid carat inversions | **0 / 56** | N/A (policy) |

Live `predictS28` matches Python artifact: **10.6151%** vs **10.6149%** MAPE.

### 3.4 S29 — hybrid scaffold (2026-06-01)

**Architecture:**

```text
S28 monotone surface (always)
  + per-spec cell offset (EB, shape_style||color||clarity)
  + cut-stratified offset (Tier A / B)
  + support-shrunk monotone LightGBM residual (zero on held-out benchmark cells)
```

**Trainer:** `research/scripts/train-s29-hybrid.py`  
**Artifact:** `research/data/starsgem-ml-model-s29-hybrid.json`  
**Reports:** [`S29-implementation-report.md`](S29-implementation-report.md), [`S29-implementation-audit.md`](S29-implementation-audit.md)

**Python results (corrected S26 baseline):**

| Split | S29 | S28 | S26 |
|-------|-----|-----|-----|
| Dense in-cell (support ≥ 20) | 9.42% | 9.42% | **4.89%** |
| Held-out benchmark cells | 17.80% | 17.80% | **5.23%** |
| Sparse tier (cell holdout) | **290%** | 17.80% | — |

**Decision rules:** **1/4** passed. Held-out cells intentionally = pure S28 (no anchor leakage across carat bands). One clarity-ladder inversion on full hybrid from offsets.

**Blocking issue for Node:** Embedded surface in S29 artifact ≠ standalone `predictS28` — Node row-holdout S29 MAPE **22.9%** vs S28 **10.6%**. Do not benchmark or ship S29 in Node until surface block re-exported from S28 trainer.

### 3.5 S30 — bounded smooth median (2026-06-01)

**Architecture:** Per `shape_style||color||clarity||typeName||cutTier` (fallback without cutTier): bin medians → local smooth → Catmull-Rom → **clamp** to observed min/max; flat endpoints outside support.

**Docs:** [`S30-bounded-smooth-median-prototype.md`](S30-bounded-smooth-median-prototype.md)  
**Scripts:** `train-s30-bounded-smooth.mjs`, `s30-predict.mjs`, `benchmark-s30.mjs`

**Row holdout (fair = curves from train rows only):**

| Variant | MAPE | MdAPE | n |
|---------|------|-------|---|
| S30 fair | **4.54%** | 1.70% | 4,264 |
| S30 shipped (all rows in medians) | 3.93% | 1.43% | 4,323 |
| S26 | 5.37% | 1.94% | 4,415 |

**Limitations:** ~**3%** of holdout rows lack a curve; no cross-grade transfer; clamps tails; can inherit local grade inversions from noisy medians. **Use for explainer/charts**, not billing, until monotone grade layer + held-out cell gates exist.

### 3.6 S31 — guarded monotone anchor (2026-06-01)

**Architecture:**

```text
S28 v0.4 monotone surface
  + support-shrunk empirical anchor
  + monotone-projected total log($/ct) grid
```

**Scripts:** `train-s31-guarded-anchor.mjs`, `s31-predict.mjs`  
**Artifact:** `research/data/starsgem-ml-model-s31-guarded-anchor.json`

| Benchmark | S31 | S28 v0.4 | S26 |
|-----------|-----|----------|-----|
| Row holdout MAPE | 8.49% | 10.62% | **5.37%** |
| Held-out cells (trainer) | 9.89% | **9.62%** | **5.31%** |
| Monotonicity grid | **0** violations | pass | display-guarded |

S31 improves **level** on warm rows (−2.1pp vs S28) but **does not beat S28 on cold cells** — anchor helps where similar rows exist, not sparse transfer. Production decision: continue only if held-out cells improve, not row holdout alone.

## 4. Constraints (hard requirements)

These are **product and market rules**, not optional regularization.

### 4.1 Ordered attributes (white diamond)

| Attribute | Order | Direction of $/ct |
|-----------|-------|-------------------|
| Clarity | IF > VVS1 > … > SI2 | Better → **higher** |
| Color | D > E > … > J | Better → **higher** |
| Carat (fixed spec) | larger | Larger → **higher** $/ct |
| HPHT vs CVD | same spec | HPHT ≥ CVD |

Registry: [`monotonic-models-and-generalized-grade-modifier.md`](monotonic-models-and-generalized-grade-modifier.md)

### 4.2 Continuous surface (design target)

[`continuous-pricing-surface-principles.md`](continuous-pricing-surface-principles.md): buckets **count** stones; **carat as float** prices stones. Magic weights at 1, 1.5, 2, 3, 4, 5, 10, 20 ct — **not** at spreadsheet `carat_bucket` walls.

### 4.3 Allowed vs forbidden discontinuities

| Allowed | Forbidden |
|---------|-----------|
| Ramp/step near magic weights | Step only from bucket label change |
| Different log-carat segment slopes | Flat $/ct across 2.8–3.2ct then bucket cliff |
| Cell anchor on smooth surface | Single average over commodity + premium modes |

### 4.4 S28 v0.4 acceptance gates

1. Zero clarity inversions on full color×clarity grid (ROUND).
2. Zero white-color inversions on grid.
3. Zero HPHT < CVD inversions.
4. Zero carat $/ct inversions on **full** `{D..K} × {IF..SI2}` grid (not only D IF).
5. Segment MAPE by carat band and shape.
6. Pinned large-stone cases above S25 floor.
7. Training from `dataset-clean-training.json`.
8. **Live Node ↔ Python artifact parity** on report-hash holdout.

**Status:** v0.4 passes 1–4 and 8. **Level** on dense commodity cells still trails lookup (~5pp MAPE gap vs S26).

## 7. Why one model cannot “just learn everything”

See [`ml-extrapolation-vs-in-sample-accuracy.md`](ml-extrapolation-vs-in-sample-accuracy.md).

**Summary:**

- **S26 low MAPE** = reconstructing lookup (interpolation).
- **S28 v0.4** = constrained law (extrapolation); ~5pp behind S26 on dense rows by design.
- **S30** = local median law; best where data exist; silent or flat elsewhere.
- **Trees** = local patches; **lookup** = stairs.

Within-cell multi-modality sets a practical **MAPE floor ~4–5%** on dense cells without latent mode labels (cut tier, list era).

## 9. Evaluation protocol (required before “X is better”)

### 9.1 Splits

| Split | Purpose |
|-------|---------|
| **reportHash % 5** | Row holdout (~4,415 rows); matches S28 trainer |
| **S29 cell holdout** | `md5(cellKey)/1000 < 0.2` — cold benchmark cells |
| **S31 cell holdout** | `cellHash(benchmarkCellKey) % 5 === 0` |
| **High carat / sparse / leave-shape-out** | Tail and OOD behavior |
| **S30 fair vs shipped** | Detect median leakage (~0.6pp optimistic) |
| **Pinned cases** | Regression smoke |

**Do not** claim victory on global row MAPE alone when anchors or lookup leak cell structure.

### 9.2 Metrics

```text
MAPE / MdAPE / p90 APE / bias %
By carat bucket, shape_style, support tier
Pinned case absolute error
Full-grid carat / color / clarity monotonicity (not only D IF)
Trainer ↔ Node parity (PASS/FAIL)
```

### 9.3 Pinned white-diamond cases

| # | Spec | Check |
|---|------|--------|
| P1 | 3.00ct ROUND E VS1 ID selected-spec | ~$109/ct commodity, not EX tail |
| P2 | 7.77ct ROUND E VS1 | Not below ~$180/ct floor |
| P3 | 5.21ct HEART D VS1 | Specialty scarcity |
| P4 | 40ct ROUND E VS2 vs SI1 | SI1 ≤ VS2 on display |
| P5 | 2.99 vs 3.01ct ROUND E VS1 | Continuous except magic band |

### 9.4 Production release gates

From [`production-white-ml-model-decision.md`](production-white-ml-model-decision.md):

```text
Do not replace S26 unless the candidate:
  1. is within 1pp of S26 on dense row holdout,
  2. beats S28 on held-out cells,
  3. has zero carat/color/clarity monotonicity violations on standard grids,
  4. passes pinned large-stone cases,
  5. has live-vs-artifact parity.
```

**June 2026 status:** S26 ships. S31 passes #3 only. S30 not evaluated on all gates. S29 fails #1–#2 and Node parity. S28 v0.4 passes #3–#5 for surface-only scope but fails #1–#2 vs S26.

**Suggested research gates** (comprehensive report): dense tier MAPE ≤ S26 + 0.5pp **and** cold-cell MAPE ≤ S28 + 1pp **and** p90 APE not worse than S26 by > 3pp.

## 15. Conclusion

**The problem** is not “find one ML algorithm with lowest MAPE.” It is a **pricing system** that:

1. Matches StarGem’s **current competitive list** where the sheet is dense (**S26**).
2. Exposes a **continuous, monotone-in-carat** wholesale law for tools and unseen sizes (**S28 v0.4** + future anchors).
3. Trains on **style-aware, cluster-cleaned** data (`dataset-clean-training.json`).
4. Never inverts gem grade order on user-facing surfaces.

**June 2026 state:**

- **S26 remains production** — best dense-cell accuracy and MdAPE; explicit production decision.
- **S28 v0.4** is a **safe, parity-verified monotone surface** — fixes v0.2’s structural bugs; still ~5pp behind S26 on rows.
- **S30** is the strongest **fair** row-holdout prototype where curves exist — research/charts only.
- **S31** improves S28 **level** on warm rows but **not cold-cell transfer** — not production-ready.
- **S29** validates the hybrid **idea** but fails accuracy and Node parity bars.

**Something better** is the **tiered stack** (S26 → S30 → S31/S28 → R0), with continued work on held-out **cells**, parent anchors, S29 parity, and optional monotone CatBoost/EBM residuals — not a single-model swap.

Next engineering: tune S31 on cell holdout; fix S29 Node surface export; gate S30 with train-only curves; prototype CatBoost monotone on warm cells per comprehensive report §9.4.
